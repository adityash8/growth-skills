# Evidence-led growth audit

Use `growth-strategist` to frame the question and `growth-audit` for the growth-system scorecard. Use an SEO audit skill, an analytics skill, or a document/PDF skill if available and relevant. Otherwise perform the required checks directly with available tools and report any capability gaps.

Use existing audit files as the starting contract; preserve supplied originals. Agree on the audience, decision, scope, and report format before expanding the research.

1. **Bound the work.** Keep research read-only. Do not create synthetic signups, transactions, conversion events or outreach. Separate public browsing from authenticated acceptance that needs authorization.
2. **Separate source layers.** Record retrieval time, underlying observation window, query filters and whether evidence was reused. A fresh API response can contain old history. Retain selected safe evidence with a source-hash manifest; do not bundle raw credential exports.
3. **Define each metric before comparison.** Preserve population, anchor, cutoff, observation maturity, environment exclusions and identity unit. First-in-window is not first-in-retained-history. After selecting a signup anchor, test for ANY eligible completion after it; a pre-anchor minimum must not suppress later valid events. Separate exact elapsed D7, calendar-day retention and any-repeat windows. Do not treat a workflow event as all-product value in a multimode product.
4. **Reconcile money separately.** Distinguish normalized recurring stock, captured cash, refunds, recognized revenue, scheduled cancellations and past-due recovery. Never silently blend currencies, billing intervals, quantities or tiered prices. Run arithmetic/tests instead of inheriting an earlier headline.
5. **Apply, do not recite, research.** When the user requests broad coverage, inventory and screen authorized resources, then deeply read those relevant to the decision. Report screened versus read coverage honestly. Verify platform, pricing, and legal claims against current primary sources. Explicitly reject stale or unsafe playbook advice.
6. **Partition research.** Give workers separate output paths and narrow scopes for metrics, SEO, positioning, lifecycle, channels and coverage review. Respect live concurrency limits. The parent verifies claims and resolves contradictory evidence; a worker report is not proof by itself.
7. **Recover tools without unrelated system changes.** If built-in search fails, use an already available search route and primary-source retrieval. Inspect client-rendered public pages after content/animation readiness; do not call a premature blank screenshot a product defect. Strip auth query strings before logging browser redirects.
8. **Ship decisions.** Include an answer-first brief, metric dictionary, and separate facts, inferences, and recommendations. Put source and confidence beside material claims, name currencies, and give each recommendation one falsification check. Add proposed roles, acceptance checks, bounded experiments, a sequenced plan and source index; do not invent owners, deadlines, or lifts.
9. **Verify the final artifact.** Build from the reviewed source. For a PDF, inspect all pages via contact sheets, then zoom dense tables and suspected defects. Check physical text bounds, repeated table headers, secret/local-path leakage, unresolved source markers, outline destinations, and contents-page numbers programmatically. Thumbnail inspection can falsely suggest clipping or wrong pagination; confirm against full pages and extracted structure before changing the layout. For other formats, inspect the rendered output and check links, tables, and references. Re-run checks after the last edit and deliver through the requested channel.

## Output contract

- Decision brief with the primary constraint, evidence strength, and unresolved contradictions.
- Metric dictionary with populations, windows, identity units, exclusions, and financial definitions.
- Source index with retrieval times, observation windows, filters, and safe evidence references.
- Ranked recommendations with proposed roles, acceptance checks, falsification checks, and bounded next steps.
- Artifact QA record and explicit limits on what was verified.

## Pitfalls and boundaries

- Pitfall: a recent retrieval timestamp does not make the underlying observation recent.
- Pitfall: a completion before a signup anchor does not rule out a valid completion after it.
- Pitfall: a polished chart does not reconcile incompatible metric definitions or currencies.
- Keep organization-specific findings in the authorized audit deliverables, outside reusable skill instructions.
- Do not deploy, publish, change credentials, enable campaigns, or send outreach as part of an audit. Prepare a separate, reviewable change request when implementation is needed.
