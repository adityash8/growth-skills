# Retention State

Use this skill when users receive initial value but the product does not become more useful over time. It designs retention into the product rather than relying on save offers or reminder campaigns.

## Inputs

- recurring job and natural usage cadence;
- activation event and retention curve by cohort;
- data, relationships, reputation, content, configuration, or workflow accumulated through use;
- what users can export, transfer, or recreate elsewhere;
- trust, privacy, portability, and regulatory constraints;
- behavior of retained, power, and churned users.

## State types

Evaluate seven forms of accumulated value:

1. **Reputation:** trusted history, reviews, rank, or credentials.
2. **Audience:** followers, subscribers, or reachable demand.
3. **Data:** history that improves decisions or output.
4. **Social graph:** relationships and interaction density.
5. **Workflow:** configurations, automations, integrations, and learned routines.
6. **Marketplace access:** liquidity, supply, demand, or verified participation.
7. **Trust-sensitive continuity:** records or processes where reliability matters.

## Procedure

1. **Separate habit from state.** Habit is repeated behavior; state is value retained from prior use. Identify both.
2. **Map current deposits.** For each core action, record what valuable state the user gains and whether it compounds.
3. **Run the portability test.** Ask what leaves with the user, what cannot, and whether the remaining value is genuine utility or hostage friction.
4. **Choose one primary state.** Select the type that follows naturally from the product's job. Avoid adding seven shallow mechanics.
5. **Design the compounding path.** Show how each deposit improves future value, discovery, trust, collaboration, or decision quality.
6. **Accelerate the first deposit.** Reduce time to the first meaningful saved item, connection, reputation signal, integration, or derived insight.
7. **Measure the causal chain.** Track state accumulated per user and compare retention for matched cohorts with different state depth.
8. **Run the regret test.** Check whether the design would still feel fair if users understood it fully and chose to leave.

## Output contract

1. **State scorecard:** fit, current deposit, compounding potential, portability, and risk.
2. **Primary state:** the one to build first.
3. **Product changes:** three to five concrete changes.
4. **Compounding loop:** deposit → improved future value → next deposit.
5. **First-deposit plan:** activation changes and metric.
6. **Retention measurement:** cohort design and decision rule.
7. **Ethics check:** value creation versus coercive lock-in.

## Guardrails

- Do not block export merely to manufacture switching cost.
- Do not confuse notifications or streaks with durable state.
- Do not claim causality from retained-user correlation alone.
- Do not retain sensitive data without a valid user need and clear controls.
- Product quality still matters; state cannot excuse a broken core job.
- Use `power-user-curve` to measure engagement depth and `saas-unit-economics-audit` to connect retention changes to economics.
